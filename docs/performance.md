# Локальная проверка нагрузки — 25 октября 2026

Среда: Windows, JDK 26.0.1, SQLite JDBC 3.53.4.0, временный локальный файл,
rollback journal, 1000 пользователей, лимит heap 256 MiB. Пул соединений не включён.
Перед замером выполнено 50 чтений для первичного прогрева.

На поток приходится 50 операций: 80% чтений модели по id, 20% чтение и save.
Время каждой операции включает ожидание, открытие соединений, SQL и преобразование
модели. Параллелизм соединений ограничен четырьмя. Ошибки учитываются отдельно.

| Потоки | Операции | Операций/с | p95, мс | p99, мс | Конфликты | Ошибки БД | Занятый heap, MiB |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 50 | 544.1 | 5.276 | 10.614 | 0 | 0 | 5.5 |
| 2 | 100 | 561.6 | 13.198 | 17.476 | 0 | 0 | 5.8 |
| 4 | 200 | 786.7 | 19.856 | 24.070 | 0 | 0 | 6.0 |
| 8 | 400 | 796.9 | 27.308 | 38.031 | 0 | 0 | 3.5 |

Это короткий диагностический прогон, не оценка максимальной ёмкости и не
сравнение с предыдущей реализацией. Число операций различается между сериями.
Heap снят после каждой серии без принудительной сборки мусора: он не является
пиковым потреблением или измерением памяти одной операции. ОС, файловый кэш,
JIT и фоновая нагрузка влияют на результат.

При переходе с 4 на 8 потоков пропускная способность почти не выросла, а задержки
увеличились. Это согласуется с лимитом четырёх соединений и ограничениями записи
SQLite; точный вклад каждого фактора этим прогоном не измерялся.

Отдельная проверка запустила **два JVM-процесса**, прочитавших одну версию пользователя.
После одновременного старта один UPDATE зафиксировался, второй получил
OptimisticLockException. Изменения не потеряны. Это проверка нескольких процессов
на одном компьютере, не распределённый тест на нескольких серверах.

Воспроизведение:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-load.ps1
```

Для оценки целевой нагрузки нужны более долгие серии с одинаковым числом операций,
репрезентативные данные, конкуренция за одни записи, разные доли записи и проверки
выбранной серверной СУБД. При её подключении тесты повторяются на настоящем драйвере.
