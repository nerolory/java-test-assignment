# Вход и сохранённая сессия

`AuthenticationController` получает `AuthenticationService`, `Executor` и `Navigator`
через конструктор. Он считывает поля в JavaFX-потоке, очищает поле пароля и передаёт
`LoginRequest` фоновой задаче. `initialize()` только настраивает интерфейс и обработчики.
Все страницы загружаются через фабрику контроллеров контейнера, включая `fx:include`.

`DefaultAuthenticationService.authenticate(request)` выполняет сценарий:

1. Проверяет поля по общим с регистрацией правилам `CredentialRules`: логин 3–128
   символов (латиница, цифры, `._-`), пароль 15–128 кодовых точек Unicode, не только пробелы.
2. Получает учётные данные через `AuthenticationRepository`. Сбой БД на этом шаге
   завершает вход исключением и не расходует попытку.
3. Учитывает попытку в `LoginAttemptLimiter`: 5 на логин и 30 суммарно за минуту
   в одном процессе. Попытка учитывается до дорогой проверки хеша, поэтому параллельные
   запросы не обходят лимит; регистр логина не даёт отдельного счётчика. При превышении
   возвращается `AuthenticationResult.Throttled` со временем повтора, хеш не проверяется.
4. Проверяет хеш пароля. Верный пароль сбрасывает счётчик логина.
5. Создаёт сессию через `SessionService` и возвращает `AuthenticationResult.Success`.

Пробелы по краям логина удаляются; пароль сохраняется без изменений. Правила и сообщения
для логина и пароля одинаковы при входе и регистрации. Неизвестный логин и неверный
пароль возвращают одинаковый результат. Для неизвестного логина выполняется проверка
подставного хеша, чтобы избежать быстрого ответа без PBKDF2.

Ошибки формы, неверные учётные данные и превышение лимита представлены отдельными
типами результата. Ошибки инфраструктуры идут через исключения. Контроллер показывает
сообщение без SQL, паролей и токенов. Повторная отправка формы блокируется до ответа.
Ошибки полей сопровождаются подсветкой. При изменении поля его сообщение и подсветка
снимаются до следующей отправки; ошибки других полей сохраняются. Общее сообщение
о неверном логине или пароле исчезает при редактировании любого из этих полей.
За отображение и сброс отвечает общий для входа и регистрации `app.ui.FormFeedback`.
Имена полей и место вывода сообщений объявлены в `login.fxml` через `properties`
(`validationField`, `validationFeedback`). Контроллер передаёт результат проверки
и корень формы; регистрация слушателей и поиск элементов выполняются общим механизмом.

## Пароли

`PasswordHasher` зарегистрирован в DI. Реализация `Pbkdf2PasswordHasher` использует
PBKDF2-HMAC-SHA256 из JDK: 600000 итераций, случайная соль 32 байта, ключ 256 бит.
Формат `users.password_hash`: `pbkdf2-sha256$600000$<salt-base64>$<hash-base64>`.
Число итераций новых хешей (`ITERATIONS`) и минимум для проверки сохранённых
(`MIN_ITERATIONS`) заданы отдельно: повышение `ITERATIONS` не блокирует старые хеши.

`DefaultRegistrationService` сохраняет результат `passwordHasher.hash(password)`.
Пароли и хеши других форматов автоматически не преобразуются. Правила регистрации
описаны в [отдельном документе](registration.md). Тестовые пользователи
создаются только во временной БД. Массивы пароля очищаются после использования. JavaFX возвращает `String`,
поэтому гарантировать стирание всех копий пароля из памяти JVM невозможно.

Параметры: [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html).
Argon2id — предпочтительный вариант OWASP для новых систем; здесь выбран PBKDF2,
доступный в JDK без дополнительной криптографической библиотеки.

## Сессия

Срок — 30 дней с момента входа, без продления при восстановлении.
В `.local/auth-session.bin` папки данных (корень проекта при запуске из исходников,
`%LOCALAPPDATA%\TestApp` для собранного exe) хранится случайный токен 32 байта, зашифрованный Windows
DPAPI с областью CurrentUser. PowerShell получает секрет через stdin, а не аргументы
командной строки. Файл заменяется атомарно и исключён из Git. При ошибке DPAPI вход
завершается ошибкой; незашифрованного запасного способа хранения нет.

Таблица `auth_sessions` содержит SHA-256 токена, ID пользователя, отпечаток хеша
пароля и срок действия. Восстановление проверяет запись, срок, наличие пользователя
и соответствие отпечатка текущему хешу пароля. Удаление пользователя каскадно удаляет
сессии. Выход сначала отзывает токен в БД, затем удаляет локальный файл.
Закрытие приложения сохраняет вход. На странице приветствия есть отдельная кнопка выхода.

`Main.init()` восстанавливает сессию вне JavaFX-потока. Если восстановление невозможно,
открывается форма входа с уведомлением. При успешном восстановлении открывается приветствие.
Просроченный или отозванный предъявленный токен удаляется. Непредъявленные истёкшие
записи остаются в БД: для длительной эксплуатации нужна периодическая очистка
`DELETE FROM auth_sessions WHERE expires_at <= <текущее время Unix в миллисекундах>`.

DPAPI требует загруженный профиль Windows текущего пользователя. Перенос защищённого
файла на другую учётную запись не является способом переноса сессии.
Описание: [Microsoft ProtectedData](https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.protecteddata).

Это локальная сессия настольного приложения. `current()` возвращает снимок пользователя
и проверяет срок, но не делает запрос в БД на каждый вызов. Смена пароля или отзыв токена
из другого процесса проверяются при следующем `restore()`. Для будущих защищённых
операций потребуется проверка сессии и прав на границе сервиса/сервера. Локальный лимит
попыток сбрасывается при перезапуске и не является распределённой защитой. Пользователь
с правом изменять SQLite-файл контролирует данные приложения.

## Схема и проверки

Для существующей базы: `./scripts/migrate-database.ps1`. Скрипт создаёт резервную копию,
применяет недостающие миграции 001/002 и сохраняет пользователей. Схема новой базы уже
содержит обе таблицы. Автоматических миграций при запуске приложения нет.

- `./scripts/test-auth.ps1` — вход, хеши, лимиты, сохранение/отзыв/истечение сессий,
  ошибки хранения и настоящий DPAPI; временная БД и временные файлы.
- `./scripts/test-ui.ps1` — настоящий FXMLLoader, DI, передача полей, фоновые задачи,
  сообщения об ошибках, переходы и выход; сервисы подменяются тестовыми.
- `./scripts/test-database.ps1` — регрессионные проверки ядра и миграций.
